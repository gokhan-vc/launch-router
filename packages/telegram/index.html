What people and machines can do

People

A wallet. A form. A signature. That’s the whole human path.

Mini App

launch.numetal.xyz/app.html — pick pad, chain, name, ticker. Advanced knobs stay visible; the matrix warns if a pad ignores them.

Connect

Browser wallet, WalletConnect, or Telegram (Privy embedded EVM wallet). Official Telegram @wallet is TON and cannot sign these deploys.

Simulate, then sign

Simulate shows the same JSON agents get from get_sign_payload. Live Sign: Clanker (SDK), Bankr (your user API key, 57% split check, no partner keys), pools.fun (wallet sends PartyFactory.launch). Unproven pads are blocked.

Telegram Mini App

People don’t type /start. They tap a link: https://t.me/botusername/appname — Telegram opens the Mini App overlay in any chat. Or they tap Launch app on the bot’s profile (https://t.me/botusername?startapp). We don’t have that bot yet, so that link doesn’t exist. Until it does, open launch.numetal.xyz/app.html (in Telegram that’s a webpage, not a Mini App). Channel: t.me/numetalxyz.

Machines

Same pads. Same payloads. Same Sign. x402 amount 0 — agents get a 402, pay $0, call.

MCP

POST /mcp JSON-RPC, or stdio npx tsx packages/mcp/src/stdio.ts. Tools: list_pads, list_networks, get_capabilities, draft_intent, simulate_launch, get_sign_payload, check_bankr_split. Same JSON as Mini App Simulate. There is no broadcast tool on this origin.

Simulate, then sign

Identical to people. Clanker: user wallet + SDK. Bankr: user’s bk_usr_ key POSTs simulate → 57% split check → live (never to this origin, never a partner key). pools.fun: user wallet sends PartyFactory.launch. Unattended agents notify the payload and stop.

REST

POST /api/v1/{tool} — body is the tool arguments. Same kernel as the Mini App.

Skill

/skill.md for Cursor, Claude, Grok, Codex, Aeon (category: crypto, mode: read-only). Interactive agents walk Sign. Unattended Aeon notifies the payload and stops.
